## Implemented behavior

- Python 3.11+ standard-library gateway binds to **127.0.0.1:18092 only**. Existing Supabase Auth session validated by `/auth/v1/user`, active non-system `admins` row, and existing `digital_chat_owner()` RPC; no client role claim or service-role key. Verified identity cached for at most 15 seconds; upstream account deactivation can therefore take up to 15 seconds. SQLite ACL removal is immediate.
- Room history, messages, audience revisions, grants/expiry, Codex thread IDs, jobs and audit trail live in SQLite on Contabo. Existing Supabase chat rows are neither moved nor deleted. No new Supabase tables/functions. No claim of measured net Supabase cost savings.
- Per-agent chat/task-request grants are owner-only. They never grant shell, production, clinical, financial or user-management authority. Access to an agent does not expose another room. Even the global owner cannot read an employee private room without membership.
- Human-only/private/mixed rooms, per-room send/manage rights, searchable staff directory, add/remove users and agents. Only owner can delegate room management; creator stays a manager. Users must have active chat grants. Directory names for delegated users come only from the owner-observed approved local directory, not unrestricted database access.
- New members default to **no previous history**. `since_seq` fences all history reads. Every audience/grant change rotates Codex context, cancels queued/running jobs, and starts a fresh engine thread. The model receives only history visible to all current members, preventing old hidden content being summarized into later replies.
- Direct one-agent rooms auto-target that agent. Groups require explicit agent selection or “اطلب رأي الوكلاء المشاركين”. Human messages without a target do not invoke models. Idempotency keys survive network-error resend in the open composer. Restart preserves history and marks ambiguous in-flight work interrupted; never silently replays a model turn.
- Codex app-server is a real stdio adapter with initialize/start/resume/turn streaming, terminal-status checks, deadline, cancellation and shared file lock. Incoming JWT never reaches Codex or its environment. Browser cannot send arbitrary RPC, process args, filesystem paths, sandbox settings or shell commands.
- **Initial channel is discussion/read-only.** Task requests are recorded `awaiting_owner`; no approval/execution endpoint claims to run them. A production execution/approval integration is deliberately not implemented in this release. Existing human-approved execution workflow remains separate.
- Other agents are selectable members, but their runtime adapter in this new gateway is **unconnected**. No fake Claude/Hapi/advisory reply is generated. Their existing owner chat continues unchanged. Connecting all other real engines remains outstanding.
- Runtime uses existing installed Codex login, disables shell/execution/apps/plugins/browser/multi-agent/hooks and configured local MCP names, denies server-initiated tool/approval requests, and uses restricted-read sandbox roots. **These settings must be verified on the actually installed Codex version and effective managed configuration, not assumed from the local fake-engine test.** Keep delegated Codex disabled until that verification passes. No fallback to unrestricted execution.
- One worker, queue cap 20, 12 messages/user/minute, four model-call reservations per UTC day persisted in gateway SQLite. The existing Issue runner has its own quota; these are NOT a unified quota or a monetary cap. Failed/ambiguous calls consume the reservation. No automatic API-key fallback or purchase.
