## 6. Traps and lessons
- **Help data version collisions:** two PRs once both used `20261125-277`. Since then every PR uses `20261126-<help no>`, unique per PR. A stamp bump within one PR uses a `-2`/`-3` suffix on the stamp, not the version.
- **Stamps across a stack:** each PR's `index.html` must keep the stamps the base branch already bumped. Rebuild index.html from the base and re-apply only your own stamps.
- **Old tests asserting old wording** (`main-treasury-balance-dom`, `treasury-dates-print-dom`): grep `tests/` for any label you change before pushing.
- **Never change branches in the main checkout while a background test run uses it;** results become garbage. Use `git worktree add` for long suite runs.
- **Hidden-attribute vs CSS:** `button[hidden]` gets overridden by `display:flex`. Add an explicit `[hidden]{display:none}`.
- **Buttons inside a closed `<details>`:** `offsetParent` is null, so "visible" checks fail. `reception-drawer.js` `pressWhenReady(...,anyVis)` handles it.
- **`today-operations.js` is loaded from `config.js`** (`loadOnce`), not index.html; bump that one line only (never rewrite config.js).
- **Finance facts:**
  - voucher `reference` is unique across the table;
  - the method is cash|bank only;
  - `is_system` accounts are hidden in the voucher form (5216/5219 refused on the dry-run);
  - the doctor statement RPCs are empty on live, so use `clinic_finance_doctor_dues`.
