## 8. Traps and lessons
- **Help merges:** after every hub merge, re-merge main into each PR. Take main's help-data / help.js / index.html, re-apply your own articles on top, set the data version above main's, re-token, then run `python3 scripts/build-dashboard-help.py` (script: scratchpad helpmerge.py, reproduced in §10).
  - When main and the PR both change the same JS file's `?v`, give it a fresh token.
- **The help coverage test** fails for new field labels until a `frule(file,label,text,article)` line is added in `scripts/build-dashboard-help.py`. A generic label like «الشهر» can collide with other files; use a unique label.
- **Arabic regexes in tests:** «للمدير» does not contain «المدير» (no alif after ل). Match on a distinctive word.
- **Python file I/O:** always `encoding='utf8'`. A default-encoding run silently failed an assert once.
- **The shared working tree:** check `git branch --show-current` before writing files. P3 was once written while on the P2 branch.
- **jsdom:** `form.reportValidity()` blocks an over-max amount before the server is called; assert "no RPC" instead of an error text.
- **PGlite mocks:** mock `post()` with the REAL direction line, or live-only refusals are missed. #864's original test mocked post() and hid the receive-only bug.
- **Dry-runs:** compute `allowed()`/role checks before `set local role authenticated` (schema permission). Seed cash through `clinic_finance.post('collection', …)`.
- **Supplier balance:** `supplier_balance` = legacy supplier_events/actions + the live reception journal.
- **Advances:** staff advances are `business_requests` kind 'advance' (subject = finance_subject from an approved 'employment'). `clinic_finance.advances` are PATIENT booking deposits.
