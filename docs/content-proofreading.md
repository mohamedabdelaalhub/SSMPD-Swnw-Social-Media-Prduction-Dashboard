# المراجعة اللغوية للمحتوى

عند إنشاء مادة أو حفظ تعديل نصي أو إرسال مسودة للاعتماد، تُراجع حقول العنوان والنص والهوك والزاوية والسكريبت والكابشن والدعوة للتفاعل وسبب الفكرة ونصوص التصميم المعروفة، بما فيها نصوص شرائح الكاروسيل داخل ناتج الوكيل. تغييرات الحالة والملفات والإعدادات وحدها لا تستدعي المراجعة.

إذا ظهرت ملاحظات، تعرض نافذة كل مقتطف أصلي وتصحيحه وسبب الملاحظة ونوعها. «تصحيح الأخطاء» يطبق الاقتراحات المعروضة ويحفظ. «أكمل بدون تصحيح» يحفظ الأصل. «رجوع للمحتوى» أو Escape يلغي الحفظ. النص السليم يكمل الحفظ مباشرة. تعذر الخدمة أو تجاوز حدود النص لا يعني اجتياز المراجعة، وتظهر إعادة المحاولة أو المتابعة بالأصل بقرار المستخدم.

المراجعة إملائية ونحوية وترقيم وتشكيل موجود فقط، وتحافظ التعليمات على اللهجة المصرية والمعنى والمعلومات الطبية والأسماء. المراجعة آلية واقتراحاتها قد تخطئ، ولا تمثل مراجعة طبية أو اعتمادًا للنشر. لا يضاف تشكيل كامل ولا إعادة صياغة. الأرقام والروابط والبريد والهاشتاجات محمية بتحقق برمجي. لا يطبق أي اقتراح مبهم أو متداخل أو غير مطابق للنص، ولا نتيجة جزئية. قرارات الاعتماد والصلاحيات وRLS كما هي.

الخدمة المستقلة content-proofread تستخدم OPENAI_API_KEY وCONTENT_AI_MODEL الموجودين على السيرفر، مع store:false. لا تكتب إلى جداول ولا تخزن نسخًا من المراجعة، ولا تسجل النص في السجلات. يُرسل فقط النص المحدد للمراجعة، بدون بيانات موظف أو مرضى أو بقية السجل. لا طلبات مع كل ضغطة أو تحديث دوري. يوجد حد 24000 حرف إجمالي و16000 للحقل و80 ملاحظة، ومهلة وإيقاف تفاعل النوافذ الخلفية. حارس طلب واحد قيد التنفيذ لكل مستخدم داخل isolate يمنع التداخل ويسمح بمراجعات متتالية لحقول النموذج ولا يدعي حدًا موزعًا عبر كل العمال.

تستخدم كل مراجعة طلبًا صغيرًا إضافيًا إلى Edge Function وخدمة النموذج. لا رفع ملفات إلى Supabase Storage. استهلاك الشبكة وتكلفة النموذج يتناسبان مع عدد المراجعات وطول النص.

اختبارات: node tests/content-proofreading.cjs وtests/content-proofreading-fixture.html للواجهة ببيانات محاكاة. لا تستبدل محاكاة النموذج بتقييم جودة لغوية على نصوص تشغيل حقيقية. بيانات الاختبارات لا تكتب إلى الإنتاج.

تحقق النشر في 22 أكتوبر 2026: النافذة المنشورة فُحصت على عروض 1280 و390 و320 ببيانات محاكاة، دون تجاوز أفقي، وتأكد تطبيق التصحيح أو حفظ الأصل وحالة التعذر. تسجيل الدخول إلى الداشبورد غير متاح في جلسة الفحص، لذلك لم يجر اختبار نموذج اللغة بطلب موظف حي أو حفظ محتوى حقيقي. الخدمة المنشورة رفضت طلبًا غير مسجل بـ401. اختبار smoke فشل في نفس شرط عدد التابات على النسخة الأصلية d03641b والنسخة المعدلة، وليس نتيجة هذه الميزة.

المواد السابقة تتيح زر «مراجعة لغوية» بجوار تعديل في تفاصيل المادة لكل من يملك صلاحية تعديلها. الزر يقرأ النسخة الحالية، يراجعها، ويحفظ فقط الحقول التي وافق المستخدم على تصحيحها دون تكرار المراجعة أو إنشاء مادة جديدة. عدم وجود أخطاء أو اختيار المتابعة بالأصل لا يكتب أي تحديث. يفحص تغيّر النسخة أو المرحلة قبل الكتابة، ولا يغير النشر أو صور التصميم أو مرحلة المادة.

إصلاح 22 أكتوبر: سجل الإنتاج أظهر طلبًا ناجحًا وطلبات 400، لكن النسخة السابقة لم تسجل فئة سبب الفشل. لا يمكن تحديد سبب كل طلب قديم من السجل وحده. أضيفت إعادة محاولة واحدة عند فشل التحقق فقط ضمن مهلة مشتركة، وفئات تشخيص دون النصوص أو بيانات النموذج. تعليمات الأسماء تسمح بتصحيح الرسم الإملائي مع الحفاظ على الهوية وتراعي سياق أية/آية والكلي/الكلى.

أسماء وتخصصات جدول العيادات كانت خارج المراجعة السابقة. الآن زر «مراجعة أسماء وتخصصات التصميم» داخل محرر جدول العيادات يراجع النص الأصلي، ويطبق اقتراحات المستخدم على الحقول والمعاينة فقط. الحفظ يراجع الجدول كذلك عند تغيّره، ثم يرسم الصورة بالنسخة التي اختارها الموظف ويحفظ brief مطابقًا لها. لا تعدّل قاعدة الأطباء أو مواعيدهم بهذا التصحيح. لا OCR للصور المرفوعة خارج القالب. لا يطلب النموذج مراجعة جديدة لنفس الجدول بعد قرار الموظف ما لم يعدّل الحقول.

اختبار daily-proofreading.cjs يفحص كود النموذج الفعلي مع محاكاة النموذج اللغوي والرسم. يغطي مصطفى وآية والكلى ووصول النص الصحيح للرسم والحفظ وحماية اليوم والأوقات وحفظ الأصل. اختبار endpoint يفحص تعافي المحاولة الثانية من مقتطف غير موجود في الأصل.
