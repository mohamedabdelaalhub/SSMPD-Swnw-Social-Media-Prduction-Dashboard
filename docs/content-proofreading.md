# المراجعة اللغوية للمحتوى

عند إنشاء مادة أو حفظ تعديل نصي أو إرسال مسودة للاعتماد، تُراجع حقول العنوان والنص والهوك والزاوية والسكريبت والكابشن والدعوة للتفاعل وسبب الفكرة ونصوص التصميم المعروفة، بما فيها نصوص شرائح الكاروسيل داخل ناتج الوكيل. تغييرات الحالة والملفات والإعدادات وحدها لا تستدعي المراجعة.

إذا ظهرت ملاحظات، تعرض نافذة كل مقتطف أصلي وتصحيحه وسبب الملاحظة ونوعها. «تصحيح الأخطاء» يطبق الاقتراحات المعروضة ويحفظ. «أكمل بدون تصحيح» يحفظ الأصل. «رجوع للمحتوى» أو Escape يلغي الحفظ. النص السليم يكمل الحفظ مباشرة. تعذر الخدمة أو تجاوز حدود النص لا يعني اجتياز المراجعة، وتظهر إعادة المحاولة أو المتابعة بالأصل بقرار المستخدم.

المراجعة إملائية ونحوية وترقيم وتشكيل موجود فقط، وتحافظ التعليمات على اللهجة المصرية والمعنى والمعلومات الطبية والأسماء. المراجعة آلية واقتراحاتها قد تخطئ، ولا تمثل مراجعة طبية أو اعتمادًا للنشر. لا يضاف تشكيل كامل ولا إعادة صياغة. الأرقام والروابط والبريد والهاشتاجات محمية بتحقق برمجي. لا يطبق أي اقتراح مبهم أو متداخل أو غير مطابق للنص، ولا نتيجة جزئية. قرارات الاعتماد والصلاحيات وRLS كما هي.

الخدمة المستقلة content-proofread تستخدم OPENAI_API_KEY وCONTENT_AI_MODEL الموجودين على السيرفر، مع store:false. لا تكتب إلى جداول ولا تخزن نسخًا من المراجعة، ولا تسجل النص في السجلات. يُرسل فقط النص المحدد للمراجعة، بدون بيانات موظف أو مرضى أو بقية السجل. لا طلبات مع كل ضغطة أو تحديث دوري. يوجد حد 24000 حرف إجمالي و16000 للحقل و80 ملاحظة، ومهلة وإيقاف تفاعل النوافذ الخلفية. حارس 4 ثوان لكل مستخدم داخل isolate يحد الدفعات السريعة ولا يدعي حدًا موزعًا عبر كل العمال.

تستخدم كل مراجعة طلبًا صغيرًا إضافيًا إلى Edge Function وخدمة النموذج. لا رفع ملفات إلى Supabase Storage. استهلاك الشبكة وتكلفة النموذج يتناسبان مع عدد المراجعات وطول النص.

اختبارات: node tests/content-proofreading.cjs وtests/content-proofreading-fixture.html للواجهة ببيانات محاكاة. لا تستبدل محاكاة النموذج بتقييم جودة لغوية على نصوص تشغيل حقيقية. بيانات الاختبارات لا تكتب إلى الإنتاج.
