# تنظيم الموارد البشرية والتعاقدات

الموارد البشرية تعرض ملخصًا وستة أقسام. ملف موظف واحد مفتوح في كل مرة، وداخله البيانات والحساب والمستندات والحضور والطلبات وروابط المستحقات والمهام. الإضافة أربعة أجزاء تحتفظ بنفس تحقق الخادم ومساري الحساب الحالي والجديد. التحضير اليدوي يبقى بديلًا واضحًا لحساب الحضور، ولا ينشئ استحقاقًا تلقائيًا.

التعاقدات تعرض الجهات والأسعار والمتابعة والتقارير في أربعة أقسام. التصنيفات الثمانية فلاتر، مع بحث بالاسم والكود ومسؤول التواصل. ملف الجهة يجمع العقود والمرضى والمتابعة والأسعار وبوابة الشراكة. بيانات الشراكات تحمل عند فتح الجزء المطلوب، وتعيد استخدام إعدادات الجهة في نفس الملف. فتح الملف لا يولد كود شراكة تلقائيًا. تجهيز الكود والرابط إجراء منفصل بصلاحية التعديل.

لم تتغير أدوار المستخدمين أو منح الصلاحيات أو RLS. إدارة الموارد البشرية تعتمد على has_hr_access أو دور المدير العام/السوبر أدمن. الوصول المالي يعتمد على صلاحيات الحسابات وأدوارها. حساب المرتب وإرساله يتطلبان إدارة الموارد البشرية وclinic_finance.allowed('create') معًا. المحاسب بدون إدارة الموارد البشرية يرى ملفه الشخصي فقط داخل HR، ولا يدير ملفات الآخرين. المدير العام والسوبر أدمن لديهما صلاحيات القسمين حسب الدور الحالي.

الروابط إلى الحسابات لا تنسخ العقود أو الأرصدة ولا تمنح صلاحية. طلب السلفة لا يصرف أموالًا. بند المكافأة أو الخصم يحتاج المراجعة الحالية. الاعتماد والصرف من الحسابات. شاشة البصمة في HR خاصة بالحضور، ورابط الدفع يفتح قسم البنوك والمطابقة بالحسابات لصاحب صلاحية العرض.

الاختبارات الجديدة organized-workspaces-dom وhr-finance-permission-boundary-sql تستخدم بيانات محاكاة ومهاجرات المشروع الفعلية. الأخيرة تثبت رفض HR-only لقراءة الحسابات وحساب أو إرسال المرتب، ورفض المحاسب لإدارة ملفات الآخرين، وإتاحة القسمين للسوبر أدمن، وعدم إنشاء قيد أو استحقاق أثناء التحقق. معاينة الواجهة لا تحفظ ولا ترسل دعوات ولا تمنح صلاحيات. لا تعتبرها تشغيلًا بحساب موظف حقيقي.
