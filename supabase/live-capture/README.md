# Live schema capture (2026-11-07)

Read-only snapshot of production objects that had no `CREATE` under `supabase/`.
Read with `pg_get_functiondef`. These files are NOT migrations. Nothing here was applied.

- Inventory and gap list: `docs/live-schema/`
- Captured: all 135 functions (clinic_reception 6, legacy_dashboard 23, performance_private 9, public 97).
- Tables: all 55 captured (20261107_tables_*.sql). 52 generated by docs/live-schema/gen_tables.py from tables-raw-20261107.txt.
  Not captured: grants, policy roles (TO ...), triggers, seed rows.
- The SQL Editor markdown export doubles backslashes; they were un-doubled here
  (checked against proposals/doctor-insurance-20261105/service-orders-rpcs.sql: `[\x00-\x1f]`).

## Finding (not fixed)
- `clinic_reception_checkin_candidates`, `clinic_reception_checkin_static`, `clinic_reception_pbx_event` use `'\\D'`
  under standard strings: that regex matches a literal backslash + D, so phones are compared without stripping
  non-digits. The repo `_screen` variants use `'[^0-9]'`. Needs live confirmation before any fix.
- `staff_kpis_admin`, `claude_autoschedule_approved`, `weekly_report_fallback` set `request.jwt.claims` to impersonate a
  super_admin / service_role inside SECURITY DEFINER code. Intentional for cron use, but worth checking who can EXECUTE them.
- `legacy_dashboard.app_secrets` still has an `api_key` text column while the key now lives in Vault. Worth checking (read-only: count non-null) whether an old plaintext key is still stored there.
- `legacy_dashboard.app_settings` policy "all read settings" is USING (true): readable by every role that has SELECT. Contents are non-secret flags.
